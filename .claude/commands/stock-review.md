# stock-review

两种独立复盘，评的对象不同，不要混着做：

- **分析质量复盘**（评工具）— 当时 skill 给出的判断（Stage/止损位/EV情景/催化剂/目标价）事后对不对？框架/skill 本身有没有系统性偏差、值得改进？**不需要真实成交记录**，只要有 `analysis.md`/`entry-*.md`/`exit-*.md` 快照、且时间已经过去够久能验证预测即可。
- **交易纪律复盘**（评人）— 你实际的买卖行为是否符合分析建议？仓位/止损纪律有没有执行？教训是给自己以后交易用的。**需要 `data/positions.md` 真实成交记录**，未平仓也能评"入场纪律"和"当前该执行但没执行"，不强制要求已经平仓。

两者可以独立跑，也可以对同一只票都跑一遍——它们回答的是完全不同的问题。

## Arguments

```
/stock-review analysis <TICKER>           # 分析质量复盘：单只标的，评skill/框架
/stock-review analysis ALL                # 分析质量复盘：横向汇总，找框架系统性偏差模式
/stock-review trade <TICKER>              # 交易纪律复盘：单只标的，评你的买卖行为（基于positions.md）
/stock-review trade ALL                   # 交易纪律复盘：横向汇总，胜率/纪律统计
/stock-review <TICKER>                    # 兼容简写：两种复盘都跑一遍（trade部分若无成交记录自动跳过并提示）
```

Optional: `--date YYYY-MM-DD` — 指定复盘哪一份快照/哪一轮交易（分析复盘按快照日期就近匹配；交易复盘按该轮 BUY 日期）；不指定则用最新的

## 模式一：`/stock-review analysis <TICKER>`（分析质量复盘 — 评工具）

**不读 `data/positions.md`**，只关心 skill 当时给出的判断对不对。

### 1. 读当时判断

- `wiki/tickers/[TICKER]/analysis.md` — 当时的 BAIT / SEPA Stage / Moneyball EV 情景
- `data/tickers/[TICKER]/entry-*.md`、`exit-*.md`（若存在）— 当时给出的 Stage 判断、止损位、目标价、催化剂预告
- 三者缺一不影响执行，但**全部缺失 → 停止**，无可复盘的判断快照

### 2. 拉事后走势

```bash
python scripts/ticker_scan.py TICKER --mode full --json
```

再拉快照日期→今天的日线：

```bash
python -c "
import yfinance as yf, sys
sys.stdout.reconfigure(encoding='utf-8')
h = yf.Ticker('TICKER').history(start='YYYY-MM-DD', interval='1d')
for d, r in h.iterrows():
    print(d.date(), round(r['Close'],2), int(r['Volume']))
"
```

### 3. 验证可验证预测

逐条对照当时文件里的预测，标 ✅兑现 / ❌证伪 / ⏳未到期：

| 预测 | 验证方法 |
|------|---------|
| Stage 判断 | 决策日后走势是否符合当时 Stage 定性（如判 Stage 1 → 后续确实横盘/下行？）|
| 止损位质量 | 若跌破：跌破后 20 个交易日内 V 型反弹收复（止损太紧）还是继续跌（止损正确）|
| EV 情景 | 现价落在 Bull/Base/Bear 哪个轨道；当时概率给得是否靠谱 |
| 催化剂 | 预告的事件（财报/合同/政策）是否如期发生、方向对不对 |
| 目标价 | T1/T2 是否到达过 |

### 4. 框架校准扫描

Step 3 验证的是「这一次判断对不对」。这一步找的是**skill 本身可能存在的系统性问题**——不是这一轮判断错了，而是判断的*方法*可能有问题：

#### ① 触发器设计缺陷

论点破裂条件写成「X 事件 **且** 价格 <$N」，结果 X 事件发生时价格差一点点，技术性未击发——逻辑上无懈可击，实质风险已经到了。

**查法：** 逐条检查 `analysis.md` 里的破裂触发器，分类为**事件型**还是**价格阈值型**。对每个价格阈值型问一句：

> 「如果当时价格再差 1%，这条会不会击发？如果会 —— 那它真正想捕捉的是价格，还是事件？」

答案是「事件」却写成价格 → 触发器设计问题，建议改为锚定事件本身。

#### ② 论点复审逾期

`analysis.md` 的 `Last updated` 距最近一次关键决策（或今天）已隔数月，期间基本面和价格都变了，但没人去重新验证。

| 间隔 | 判定 |
|------|------|
| ≤30 天 | ✅ 正常 |
| 31–60 天 | ⚠️ 偏旧，且期间价格变动 >20% → 记框架问题 |
| >60 天 | ❌ 复审逾期，无论价格 |

#### ③ 数据口径错误（与框架本身无关，但会污染判断输入）

脚本口径 bug 让涨跌幅、缺口、均线偏离等被系统性算错，判断建立在污染的数据上。

**查法：交叉验证**——同一指标用两条独立路径各算一次：

```bash
python -c "
import yfinance as yf
t = yf.Ticker('TICKER'); i = t.info
h = t.history(period='5d')['Close']
quote_pct = (i['regularMarketPrice']/i['regularMarketPreviousClose']-1)*100
hist_pct  = (h.iloc[-1]/h.iloc[-2]-1)*100
print(f'quote口径 {quote_pct:+.2f}%  history口径 {hist_pct:+.2f}%')
print('⚠️ 不一致，history 可能缺 bar' if abs(quote_pct-hist_pct)>0.5 else '✅ 一致')
"
```

发现不一致 → **判断本身可能没错，是输入错了**。修法是加测试/修脚本，不是改框架判断逻辑。

### 5. 分析质量打分 + 框架改进建议

| 项 | 评分 | 理由 |
|----|------|------|
| 分析质量（综合 Step3 预测兑现率）| ✅/⚠️/❌ | [1句] |

**框架改进建议**（若 Step4 发现系统性问题）：

> 具体到哪个 skill 文件/哪条判断规则——如"止损公式 `max(2×ATR, 10%)` 在 `atr_pct>15%` 的高波动标的上历史上多次被打掉后 V 型反弹，建议 `/stock-entry.md` 对高 ATR 标的放宽止损宽度上限"；或"`/stock-analyze.md` Moneyball Bear 情景概率在过去 N 次复盘中系统性偏低，建议同类情景默认 +5-10pp"

无系统性问题 → 写"本轮未发现框架层面问题"

### 6. 输出报告

保存到 `data/tickers/[TICKER]/review-analysis-[YYYY-MM-DD].md`：

```markdown
# [TICKER] 分析质量复盘 — YYYY-MM-DD

## 复盘对象
- analysis.md（日期）/ entry-*.md（日期）/ exit-*.md（日期）

## 预测验证
| 预测（出处） | 当时判断 | 实际走势 | 裁决 |
|------|---------|---------|------|
| Stage（entry）| ... | ... | ✅/❌/⏳ |
| 止损位（entry）| $X | 跌破后... | ✅/❌ |
| EV 情景（analysis）| Bull $X/Base $X/Bear $X | 现价 $X 落在... | ... |
| 催化剂（analysis）| ... | ... | ... |

## 框架校准扫描
| 项 | 结果 | 说明 |
|----|------|------|
| 触发器设计 | ✅/⚠️ | [1句] |
| 复审时效 | ✅/⚠️/❌ | 间隔X天 |
| 数据口径 | ✅/⚠️ | [1句] |

## 分析质量打分
| 项 | 评分 | 理由 |
|----|------|------|
| 分析质量 | ✅/⚠️/❌ | [1句] |

## 框架改进建议
- [具体到文件+规则的建议 / 本轮未发现框架层面问题]
```

新建议 → 追加到 `wiki/skill-improvements.md`（若不存在则创建，格式同 `wiki/lessons.md` 但类型标签为「框架」，人工决定是否真的去改 `wiki/frameworks/*.md` 或对应 `.claude/commands/*.md`，**不自动改**）

## 模式二：`/stock-review trade <TICKER>`（交易纪律复盘 — 评人）

**必须读 `data/positions.md`**，评估你自己的买卖行为。**不要求已平仓**——未平仓也能评入场纪律和当前是否该执行但没执行。

### 1. 读成交记录

- `data/positions.md` — 该 ticker 全部成交行。**无成交记录 → 停止**，提示先补 positions.md（这本身就是纪律问题的一种：没记录的交易不能复盘）
- 关联的 `data/tickers/[TICKER]/entry-*.md`、`exit-*.md`（按关联文件列/日期就近匹配）。**无 entry 快照 → 继续复盘，但直接记教训「记录/无分析入场」**（无分析依据就下单，属纪律问题）
- 判断该轮是否已平仓：有对应 SELL 且股数清零 → 已平仓；否则 → 未平仓，仍可复盘"入场纪律"+"当前纪律状态"

### 2. 入场纪律核查

对照 `entry-*.md` 建议 vs 实际成交：

| 项 | 建议 | 实际 | 裁决 |
|----|------|------|------|
| 入场价位 | 建议区间 $X-$X | 实际 $X | ✅在区间内 / ⚠️追高超区间 |
| 仓位 | 建议股数 X | 实际股数 X | ✅符合 / ⚠️超配 / ⚠️低配 |
| 止损设置 | 建议 $X | 实际记录的止损 | ✅一致 / ❌未设置或不一致 |

### 3. 持仓中纪律核查（仅未平仓时执行）

```bash
python scripts/ticker_scan.py TICKER --mode full --json
```

对照现价与 `entry-*.md`/最新 `exit-*.md` 记录的止损位：

- 现价已跌破止损位（连续多日）但 `positions.md` 无对应 SELL → **纪律违规：止损未执行**，直接记教训，不等平仓
- 现价已到目标位但未按计划减仓 → ⚠️ 记录，非硬性违规（可能是主动选择持有），但需在报告中列出

### 4. 平仓纪律核查（仅已平仓时执行）

对照 `exit-*.md` 写下的止损价/目标价/自由股规则 vs 实际 SELL 价格和时机：

| 项 | 计划 | 实际 | 裁决 |
|----|------|------|------|

**标签豁免止损检查**（常见失效模式）：`exit-*.md` 白纸黑字写了止损价，但 `positions.md` 备注标签（「长期持有」「论点止损」「无硬止损」之类）让它从未被执行。

**查法：** 拉该轮持仓期间最低/最高价，对照 `exit-*.md` 数字条件：

```bash
python -c "
import yfinance as yf, sys
sys.stdout.reconfigure(encoding='utf-8')
h = yf.Ticker('TICKER').history(start='BUY_DATE', end='SELL_DATE', interval='1d')
print('区间最低', round(h['Low'].min(),2), '最高', round(h['High'].max(),2))
"
```

条件被触及但无对应及时 SELL → **纪律违规**，无论最终盈亏都记教训。

> 判据：标签可以豁免*机械*止损（如蓝筹不按技术止损），但不能豁免一个**明确写下日期和价格**的出场计划。同时存在标签和 `exit-*.md` 时，出场计划优先。

### 5. 结果（仅已平仓时打分，未平仓显示浮动盈亏不计入结果层）

| 项 | 评分 | 理由 |
|----|------|------|
| 纪律执行 | ✅/⚠️/❌ | [1句] |
| 结果 | ✅/⚠️/❌/⏳持仓中 | 盈亏 $X（±X%）或"浮动盈亏 $X（±X%），未平仓" |

> 四象限提醒：纪律✅结果❌ = 正常亏损（过程对，接受）；纪律❌结果✅ = 运气（危险，勿强化，仍要记教训）。

### 6. 输出报告

保存到 `data/tickers/[TICKER]/review-trade-[YYYY-MM-DD].md`：
> 产出属私有交易数据（`.gitignore` 已排除 `data/` 相关路径），**勿 commit**。

```markdown
# [TICKER] 交易纪律复盘 — YYYY-MM-DD

## 交易记录
- BUY YYYY-MM-DD $X ×N股 [→ SELL YYYY-MM-DD $X ×N股 / 持仓中]
- 状态：已平仓，盈亏 $X（±X%）| 持仓X天 —— 或 —— 未平仓，浮动盈亏 $X（±X%）
- 关联：entry-*.md / exit-*.md（日期）

## 入场纪律
| 项 | 建议 | 实际 | 裁决 |
|----|------|------|------|

## 持仓中/平仓纪律
[视是否已平仓填对应核查结果]

## 打分
| 项 | 评分 | 理由 |
|----|------|------|
| 纪律执行 | ✅/⚠️/❌ | [1句] |
| 结果 | ✅/⚠️/❌/⏳持仓中 | [1句] |

## 教训
- [新教训 → 已追加 lessons.md L00X / 重犯 → L00X 计数+1 / 无新教训]

## 下一步
- [若未平仓：当前该不该已经止损 / 若已平仓：重入条件 / watchlist / 无]
```

教训写入 `wiki/lessons.md`：新教训按条目格式追加，来源填 `review`；同类教训不新增，原条目 `×N` 计数+1 并加 `; 重犯: 日期 ticker`

### 模式二 ALL：`/stock-review trade ALL`（交易纪律汇总）

### 1. 盘点

- 扫 `data/tickers/*/review-trade-*.md` 全部单笔纪律复盘
- 扫 `data/positions.md` 全部交易轮次（含未平仓）；**未复盘的轮次列清单**，建议先跑单笔（不强制阻断）
- 未平仓持仓单独列出（不参与胜率统计，但列出"当前纪律状态"——是否有止损未执行的红旗）

### 2. 横向统计

- 胜率 = 盈利轮次 / 已复盘平仓轮次；盈亏比 = 平均盈利 / 平均亏损
- 纪律/结果打分分布（各项 ✅/⚠️/❌ 计数）
- **重复错误模式**：按 `wiki/lessons.md` 类型标签聚类（如「3 次亏损中 2 次为 纪律/止损未执行」）
- 四象限统计：纪律对结果差（正常）vs 纪律差结果好（运气，重点警示）

### 3. 输出

保存到 `data/reviews/summary-trade-[YYYY-MM-DD].md`：
> 产出属私有交易数据（`.gitignore` 已排除 `data/` 相关路径），**勿 commit**。

```markdown
# 交易纪律复盘汇总 — YYYY-MM-DD

## 总览
- 已复盘轮次：X | 胜率：X% | 盈亏比：X | 总盈亏：$X
- 未复盘的轮次：[清单或 无]
- 持仓中：[清单 + 当前纪律状态红旗]

## 打分分布
| 项 | ✅ | ⚠️ | ❌ |
|----|----|----|----|

## 重复错误模式
| 类型 | 次数 | 涉及 | 对应教训 |
|------|------|------|---------|

## 建议
- [最高频错误 → 建议动作]
```

## 兼容简写：`/stock-review <TICKER>`

等价于对该 ticker 依次跑「模式一：分析质量复盘」+「模式二：交易纪律复盘」。若 `data/positions.md` 无该 ticker 成交记录，跳过模式二并在输出中提示：`⚠️ 未找到 <TICKER> 成交记录，仅完成分析质量复盘；如需交易纪律复盘，先在 positions.md 记录成交`。
