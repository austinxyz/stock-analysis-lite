## ⚠️ 核心发现：入场判断建立在滞后1个交易日的价格上

`entry-2026-07-26.md` 用"现价$91.24"作为决策锚点，但这实际是 **7/23 收盘价**。真实价格路径（WebSearch + yfinance交叉验证）：

| 日期 | 收盘价 | 说明 |
|------|--------|------|
| 7/23 | $91.24 | entry-2026-07-26.md 用的"现价" |
| 7/24 | **$74.92**（另一数据源$71.59）| 财报后单日暴跌-17.9%，entry生成时这天已经收盘 |
| 7/27（复盘日）| $63.82-$64.86 | 继续下跌 |

`entry-2026-07-26.md` 生成于（标注）2026-07-26（周日），此时最近一个交易日应是7/24，真实"现价"应为$74.92左右，而非$91.24。**当时`scripts/ticker_scan.py`对7/24这天的yfinance日线数据缺失做了静默丢弃回退**（本session后来才修复，加了`latest_bar_missing`/`live_price`兜底字段）——这正是那个bug的实例。

用$91.24（比真实价高约+21.8%）做锚点，直接导致：
- Entry计划判断"Stage2健康趋势、趋势模板7/8、现在可入"——若当时用真实价$74.92，MA50/趋势模板会立刻反映7/24暴跌，大概率不会给出"现在可入"结论
- PW EV检查"现价$91.24 < EV×0.85=$98.39 → 可入"——这个安全边际判断本身建立在虚高的现价上，失去意义

## 框架改进建议

1. **【最高优先级】`/stock-entry.md`、`/stock-analyze.md` 需要补上数据延迟检查步骤**——`/ticker-scan.md`已经加了"若`latest_bar_missing==true`，对比`live_price`偏离幅度≥10%则标注滞后警告并降级"，但`/stock-entry.md`/`/stock-analyze.md`还没有类似逻辑。建议在两个文件的 Step 1（拉数据）之后立即加：若`latest_bar_missing==true`，强制改用`live_price`重新评估入场条件/技术面判断，而非直接用滞后的`price`字段
2. **Moneyball Bear情景校准偏乐观**——本轮Bear目标$68被现价$63.82跌破。建议对"forward P/E已显著偏高 + 近期已有系统性抛售信号"的标的，Bear情景不应只锚定"回归历史估值中位数"，需额外为"基本面质疑引发恐慌性抛售"这类尾部场景预留更大下行空间（如Bear目标再下修10-15%，或Bear概率上调）
3. **`wiki/tickers/[TICKER]/analysis.md` 版本管理问题**——当前是同路径覆盖，历史判断无法追溯。建议比照entry/exit改为按日期存档（如`analysis-2026-07-26.md`），复审时新建文件而非覆盖，或至少在覆盖前把旧版本归档到`changelog.md`
